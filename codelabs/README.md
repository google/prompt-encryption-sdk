# Prompt Encryption SDK - Automated Codelab Scripts

This directory contains bash scripts to automate the end-to-end deployment of a secure vLLM inference server running `google/gemma-3-1b-it` inside Google Cloud Confidential Space.

## Prerequisites

Before running these scripts, ensure you have:
1. `gcloud` CLI installed and authenticated.
2. A Google Cloud project with billing and required quota (A3/H100).
3. A Hugging Face account with a User Access Token. You must accept the Gemma 3 license agreement on Hugging Face to access the model weights.

## 1. Setup the Infrastructure

The `setup.sh` script will enable required APIs, build and push the Docker image, create a Service Account with necessary IAM roles, spawn the Confidential VM, and configure an external TCP Load Balancer.

Since we are using the gated Gemma 3 model, you must export your Hugging Face token first:

```bash
export HF_TOKEN="your_hugging_face_token_here"
bash setup.sh --project-id <YOUR_PROJECT_ID>
```

## 2. Wait for the Server to become Healthy

After the setup script finishes, the Confidential VM takes several minutes (usually 4-6 minutes) to boot the hardened OS, install NVIDIA drivers, download the model weights from Hugging Face, and allocate the KV cache on the GPU.

**Do not proceed to the next step until the load balancer reports the backend as `HEALTHY`.** You can check the health status by running the following command:

```bash
gcloud compute backend-services get-health secure-inference-backend \
    --region=us-central1 \
    --project=<YOUR_PROJECT_ID>
```

*Keep running this command periodically until you see `healthState: HEALTHY` in the output instead of `UNHEALTHY`.*

## 3. Run the Client

Once the server is healthy, run the client script. It will automatically read the Load Balancer IP and Image Hash generated by the setup script, perform the Attested TLS handshake, and securely send a prompt to the Gemma 3 model.

This remains the default server-attestation-only flow; the client may run on
your workstation exactly as before.

```bash
bash run_client.sh <YOUR_PROJECT_ID>
```

## Optional: Mutual Attestation

Mutual attestation requires a different deployment shape: the client must also
run as a Confidential Space workload so it can issue its own GCA token through
the Confidential Space UDS or GoTPM. A laptop process cannot produce valid
client evidence.

### 1. Build the confidential client workload

The repository includes `examples/MutualClient.Dockerfile`, which installs the
SDK and runs `examples/test_client.py` in mutual mode:

```bash
CLIENT_IMAGE="gcr.io/<CLIENT_PROJECT_ID>/prompt-encryption-mutual-client:v1"
docker build -t "${CLIENT_IMAGE}" -f examples/MutualClient.Dockerfile .
docker push "${CLIENT_IMAGE}"
gcloud container images describe "${CLIENT_IMAGE}" \
    --format="value(image_summary.digest)"
```

Record the immutable digest printed by the final command. This is the client
measurement the inference server will trust. The client workload must be able
to reach the inference load balancer.

The client image is generic: provide the following values through its
Confidential Space launch configuration rather than rebuilding it for each
inference server:

- `SERVER_IMAGE_HASH`: inference server image digest that the client verifies;
- `SERVER_LB_IP`: inference server load-balancer address;
- `SERVER_PROJECT_ID` and `SERVER_ZONE`;
- optional `SERVER_HW_MODEL` (`TDX` by default);
- optional `ATTESTATION_TYPE` (`uds` by default, or `gotpm`).

### 2. Configure the inference server to require that client

On a fresh codelab deployment, pass the confidential client's image digest to
`setup.sh`:

```bash
export HF_TOKEN="your_hugging_face_token_here"
bash setup.sh \
    --project-id <SERVER_PROJECT_ID> \
    --mutual-attestation \
    --trusted-client-image-hash "sha256:<CLIENT_IMAGE_DIGEST>" \
    --trusted-client-project-id <CLIENT_PROJECT_ID> \
    --trusted-client-zone <CLIENT_ZONE> \
    --trusted-client-hw-model TDX
```

This supplies `client_policy` to `run_uvicorn_app` and sets
`require_mutual_attestation=True`. Consequently, the normal workstation
`run_client.sh` is intentionally rejected by this deployment. Use distinct
resource names if you want to keep the original and mutual codelabs running at
the same time.

The example server reads these launch settings:

- `REQUIRE_MUTUAL_ATTESTATION`
- `TRUSTED_CLIENT_IMAGE_HASH`
- `TRUSTED_CLIENT_PROJECT_ID`
- `TRUSTED_CLIENT_ZONE`
- `TRUSTED_CLIENT_HW_MODEL`

For a production deployment, treat this policy as security-critical measured
configuration: pin or authenticate it rather than allowing an untrusted
operator to weaken it at launch.

### 3. Run the client inside Confidential Space

The supplied client image starts automatically after the variables above are
provided. If you instead have an interactive Confidential Space client with the
repository checked out, run:

```bash
bash codelabs/run_mutual_client.sh <SERVER_PROJECT_ID> <SERVER_ZONE> uds
```

Use `gotpm` as the last argument when the client image provides the GoTPM CLI:

```bash
bash codelabs/run_mutual_client.sh <SERVER_PROJECT_ID> <SERVER_ZONE> gotpm
```

The wrapper accepts `SERVER_IMAGE_HASH` and `SERVER_LB_IP`, or falls back to the
`.image_hash` and `.lb_ip` files produced by the server setup. It calls the same
example client with two additional options:

```bash
PYTHONPATH=src python3 examples/test_client.py \
    --image-hash "$(cat .image_hash)" \
    --project-id <SERVER_PROJECT_ID> \
    --zone <SERVER_ZONE> \
    --ip "$(cat .lb_ip)" \
    --hw-model TDX \
    --mutual-attestation \
    --attestation-type uds
```

The client creates its ephemeral ECDSA and ML-DSA identity under `/dev/shm`,
obtains a TEE token, verifies the server proof, and only then returns its own
channel-bound proof. The server does not authorize inference traffic until that
second proof passes its configured client policy.

## 4. Cleanup

To avoid ongoing compute charges for the A3 instance and Load Balancer, ensure you tear down all created resources once you are done experimenting:

```bash
bash cleanup.sh --project-id <YOUR_PROJECT_ID>
```
